# Power BI Build Guide

Step-by-step instructions to build the actual `.pbix` file from this
project's specification. No `.pbix` is included in this repository (see
`dashboard_requirements.md`) -- this guide is how a reader recreates it.

## Prerequisites

- Power BI Desktop (free download from Microsoft).
- `data/processed/orders_clean.csv`, generated by running
  `python run_analysis.py` from the project root. **Do not import the raw
  Excel file** -- it contains PII columns this project's privacy
  requirements exclude.

## Step 1: Import and shape the data

1. Power BI Desktop -> Get Data -> Text/CSV -> select
   `data/processed/orders_clean.csv`.
2. In Power Query Editor, verify column types: `order_date`/`ship_date` as
   Date, `sales`/`profit`/`discount` as Decimal Number, `quantity`/`row_id`
   as Whole Number, everything else as Text.
3. Duplicate this query 4 times (right-click -> Duplicate) to create the
   dimension tables, per `dashboard_data_dictionary.md`:
   - **DimProduct**: keep only `product_id, product_name, category,
     sub_category`, then Remove Duplicates.
   - **DimCustomer**: keep only `customer_id, segment`, then Remove
     Duplicates.
   - **DimGeography**: keep only `country_region, region`, then Remove
     Duplicates.
   - Rename the original full query to **FactSales**.
4. In FactSales, you can optionally remove the columns now covered by
   dimension tables (`product_name, category, sub_category, segment,
   country_region`) to keep the fact table narrow -- keep the ID columns
   (`product_id, customer_id, region`) as relationship keys.

## Step 2: Build DimDate

1. Modeling tab -> New Table, paste:
   ```dax
   DimDate =
   ADDCOLUMNS(
       CALENDAR(DATE(2023,1,1), DATE(2026,12,31)),
       "Year", YEAR([Date]),
       "Quarter", QUARTER([Date]),
       "Month", MONTH([Date]),
       "MonthName", FORMAT([Date], "MMMM"),
       "YearMonth", FORMAT([Date], "YYYY-MM"),
       "YearQuarter", YEAR([Date]) & "-Q" & QUARTER([Date])
   )
   ```
2. Select the DimDate table -> Table Tools -> Mark as Date Table -> choose
   the `Date` column.

## Step 3: Build relationships

Modeling tab -> Manage Relationships -> New, and create each relationship
listed in `dashboard_data_dictionary.md`'s Relationships table (all
1:many, single-direction, dimension -> fact). Power BI's autodetect
usually gets most of these right from matching column names, but verify
cardinality and direction on each one.

## Step 4: Create the measures

1. Create a new blank table: Modeling -> New Table -> name it `_Measures`,
   formula: `_Measures = {BLANK()}`. This keeps measures organized outside
   any physical data table.
2. Copy every measure from `dax_measures.md` into `_Measures` (Modeling ->
   New Measure), one at a time. Verify each against the "Actual value"
   noted in that file after creating it -- if a measure doesn't match, the
   relationship or filter context is likely wrong.

## Step 5: Build each page

Follow `dashboard_requirements.md` page-by-page. General visual mapping:

| Requirement | Power BI visual |
|---|---|
| KPI card | Card |
| Trend over time | Line Chart (X-axis: DimDate[YearMonth] or [Date]) |
| Category/Region/Segment comparison | Clustered Column Chart or Bar Chart |
| Top/Bottom N | Bar Chart, sorted, or Table with conditional formatting |
| State-level map | Filled Map (uses `state_province` -- note: this field
  was excluded as PII from `orders_clean.csv`; if state-level detail is
  required, re-derive a state-level aggregate table separately, in a form
  that reports totals only and never links back to individual customers) |
| Revenue vs. Profit outliers | Scatter Chart |
| Pareto / cumulative share | Line and Clustered Column Chart (combo) |
| Discount buckets | Clustered Column Chart with a calculated bucket column |

**Note on state-level analysis:** `orders_clean.csv` excludes
`state_province` as PII. If Page 4's state-level visual is needed, use
`outputs/tables/region_summary.csv` for region-level detail (already
PII-safe), or generate a separate state-level *aggregate* CSV (state name +
summed revenue/profit only, no row-level customer linkage) specifically
for this purpose -- state names alone, with no customer-linkable detail,
are not customer PII.

## Step 6: Add slicers and enable interactivity

1. Add slicers for Year, Region, Category, Segment on each relevant page
   (Insert -> Slicer).
2. Format -> Edit Interactions to confirm cross-filtering behaves as
   expected between visuals on the same page.
3. For drill-down (Category -> Sub-Category -> Product), build a
   hierarchy on DimProduct (right-click Category column -> Create
   Hierarchy, then drag Sub-Category and product_name into it) and use
   that hierarchy on the relevant chart's axis.
4. Use the Sync Slicers pane (View -> Sync Slicers) to share Year/Region
   slicers across all 5 pages.

## Step 7: Validate against known values

Before considering the dashboard complete, spot-check these cards against
the "Actual value" figures documented in `docs/kpi_framework.md` and
`dax_measures.md`:

- Total Revenue should read **$2,326,534.35** with no filters applied.
- Total Profit should read **$292,296.81**.
- Profit Margin should read **12.56%**.
- Total Orders should read **5,111**.

If any of these don't match, check for: (a) a many-to-many or
bidirectional relationship silently duplicating rows, or (b) a filter
left applied from earlier editing.
